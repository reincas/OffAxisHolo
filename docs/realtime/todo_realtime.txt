A. BEFUND IN KURZ
================================================================================
Was schon passt (nicht neu bauen):
  + Backend-Abstraktion NumPy/CuPy (backend.py, Array-API), Präzision single/double.
  + Rekonstruktionsreihenfolge physikalisch richtig: Filterung -> Kompensation in
    der Hologrammebene -> Propagation (processor_class.run, Notes_reconstruction_order).
  + Bandbegrenzte ASM inkl. Padding-Trick (numericalPropagation.angularSpectrum).
  + Least-Squares-Entfalten per DCT, GPU-fähig (phaseUnwrapping.phase_unwrapping_ls_dct).
  + CPU/GPU-Paritätstests vorhanden (tests/test_backend.py) - aber GPU-Teil nie auf
    echter CUDA-Hardware gelaufen (skipif ohne GPU; ToDos.txt bestätigt das).
  + Presets, Simulation (simulate.py), Container-IO (scidatacontainer).

Warum die Bibliothek so NICHT als Echtzeitkern taugt (Kern des Befunds):
  (1) Objektorientiert pro Bild: pro Messung werden Hologram, ReferenceHologram,
      HologramProcessor (inkl. DHMPlotter -> matplotlib) neu gebaut; Zustand wird
      in ~15 Attributen je Lauf abgelegt. Kein Strom-/Akkumulator-Konzept.
  (2) Nichts wird zwischengespeichert: angularSpectrum baut je Aufruf fftfreq,
      meshgrid, kz, exp, Bandmaske neu; circularMask baut je Aufruf ein Meshgrid;
      der Hintergrund wird je Lauf neu rekonstruiert (ReferenceHologram.reconstruct)
      und conj(Ub)/(|Ub|^2+eps) je Lauf neu berechnet.
  (3) IFFT immer über das volle N x N (holo2field), nicht über den ausgeschnittenen
      Seitenbandbereich. fftshift/roll/ifftshift über das ganze Bild.
  (4) Host-Synchronisationen im Pfad: bool(xp.min(holo) < 0) in holo2field und
      locate_order, to_numpy der Kandidaten in locate_order, locate_order wird
      sogar je Hologramm ausgeführt, wenn first_diffraction_order_pos fehlt.
  (5) Keine Mittelung (weder Hintergrund noch Objekt), keine Kolbenphasen-
      korrektur, keine Referenzregion.
  (6) Entfalten 'Fast 2D' erzwingt GPU -> CPU -> GPU (phase_unwrapping_fast2d).
  (7) Import-Gewicht: `import offaxisholo` zieht über __init__.py alles: cv2,
      scidatacontainer, tkinter (reconstruction_pipeline.py), matplotlib
      (Plotter/phaseUnwrapping), scikit-image. Auf einem Dienst-Rechner ohne
      Display bricht `from tkinter import ...` evtl. schon beim Import (?).
  (8) GUI-Dialoge (tkinter messagebox/filedialog) mitten in
      ReconstructionPipeline.__init__ -> blockiert in einem Dienst.
  (9) backend._state ist modulglobal und nicht thread-sicher (use_backend()
      ändert global) - unvereinbar mit Netzwerk-/Akquisitions-/Worker-Threads.
 (10) Kein Kamera-, Dienst-, Protokoll-, Client-Code, keine Zustandsmaschine.
 (11) Kompensations-eps zu klein für Echtzeit: eps = finfo.eps * max|Eref|^2 ist
      nur ein Division-durch-Null-Schutz, keine Wiener-Regularisierung.
